# Translation method conformance, version 1

These are repository-owned synthetic inputs, not third-party mod bytes.
`input/` covers padded/short/duplicate CSV rows, comment-row exclusion,
JSON keys, barewords and single quotes, loose Java comments/literals,
legacy GB18030 CSV, JSON CRLF, source exclusions, author zh/en records, and a JAR containing referenced
and non-referenced CJK constants plus a double-slot long constant.

`expected-export.json` was generated by BridgeForge's current translation
method on 2026-10-05. `translated.json` supplies explicit translations;
`expected-output/` records the exact bytes produced by applying it.
Loose Java output preserves the input line endings on every platform.
Compare complete JAR bytes as well as non-target member content. The source
JAR deliberately uses UTF-8 flags on ASCII member names and zero external
attributes, exercising reference ZipFile header normalization.

Project Go copies this same versioned directory and tests its Java export
and apply against it. Changes to the shared method require a failing
fixture/test in both repositories first. These fixtures establish only
their stated conformance boundary; real-mod and live-game validation are
separate.

The additive [schema-v1 extension profile](SCHEMA_V1_EXTENSIONS.md) and its two JSON fixtures were added on 2026-10-19.
They cover text lines, loose classes and role/group metadata without changing the original 18-unit corpus.
