## 3. Honesty boundaries

This section is a contract. The implementation must not weaken it.

1. **Static data cannot perfectly predict combat balance.** BalanceBench reports structural and statistical position within a vanilla reference class. It does not measure whether content is fun, fair, or well-designed.
2. **A missing value is never zero.** Undeterminable inputs produce `NOT_DETERMINABLE` for the affected metric, which propagates to family and verdict state (§10.0, §13) — never a silent default.
3. **An unknown script is never safe.** An uncatalogued script hook must not be silently certified as within band (§15).
4. **Compilation success is not behavioural proof.** A passing build proves nothing about the numbers BalanceBench computes.
5. **`MANUAL` is an answer.** It is not a failure of the tool and must not be suppressed to make reports look decisive.
6. **Vanilla predicts vanilla.** A vanilla entity audited against vanilla must not produce false overtuning at any meaningful rate (§20.2). This is the central calibration benchmark, not an afterthought.
7. **Every cross-mod claim is contextual.** Mods inform peer population and ecosystem notes (§16) and never contaminate the vanilla baseline.
8. **Every verdict is explainable in one sentence** (§13.2), with the peer set and the near-miss exclusions shown (§17).

## 4. Inputs and read-only rules

BalanceBench is read-only with respect to every input.

### 4.1 Inputs

| Input | Source | Mutates? |
|---|---|---|
| Vanilla reference data | a hand-identified Starsector install (`starsector-core/data/...`) | never |
| Candidate mod data | the mod's `data/` tree | never |
| Mod corpus (context only) | other installed mods | never |
| VoidSmith legality/hook output | provider boundary (§7) | never |
| Policy file | versioned, hash-bound (§19) | never during a run |
| Benchmark corpus | `benchmarks/` fixtures (§20.3) | never during a run |

### 4.2 Rules

- No input directory is ever written to, moved, or deleted.
- No game file, save, or mod archive is modified.
- The reference install is **pinned by version identity**, not by path (§19).
- Vanilla content and modded content are never blended into one statistical pool (§8.4, §16).

### 4.3 Reference installation

The reference must be an explicit, hand-identified install. A mismatch between the pinned `reference_game_version` and the detected install is a **first-class error state** (`UNVALIDATED_REFERENCE_VERSION`, §19), never a warning that is ignored.

## 5. Architecture and pipeline

```text
INPUTS                    CANDIDATE ENTITY
  vanilla data                 |
  mod data                     v
  provider output  --->  [ 1. LOAD    ]  table substrate (§6)
                                |
                                v
                         [ 2. COHORT  ]  hard structural eligibility (§8)
                                |
                                v
                         [ 3. PEERS   ]  leakage-safe selection (§9)
                                |
                                v
                         [ 4. METRICS ]  registry + transforms (§10)
                                |
                                v
                         [ 5. STATS   ]  percentile + envelope (§11)
                                |
                                v
                         [ 6. SHAPE   ]  gaps / multimodality (§11.3)
                                |
                                v
                         [ 7. FAMILY  ]  anti-correlation aggregate (§12)
                                |
                                v
                         [ 8. SCRIPT  ]  graded evidence state (§15)
                                |
                                v
                         [ 9. VERDICT ]  family-count rules (§13)
                                |
                                v
                         [10. CONF    ]  evidence quality (§14)
                                |
                                v
                         [11. REPORT  ]  deterministic, hash-bound (§17, §19)
```

### 5.1 The one architectural rule that matters most

> **A metric being judged must never select its own comparison peers.**

This is the peer-selection leakage rule (§9). It is the single change that most affects whether a conclusion is trustworthy. It is enforced as an executable invariant (§20.5), not just prose.

### 5.2 Module layout (proposed)

```text
balancebench/
  __main__.py        CLI entry
  tables.py          load canonical tables (§6)
  providers/         VoidSmith adapter + local fallback (§7)
  cohorts.py         hard structural eligibility (§8)
  peers.py           leakage-safe peer selection (§9)
  metrics/
    registry.py      Metric Specification Registry (§10.0)
    weapons.py       Phase 1 weapon metrics
    hulls.py         Phase 1 hull metrics
  stats.py           percentile, envelope, shape (§11)
  families.py        family aggregation (§12)
  scripts.py         graded script evidence (§15)
  verdict.py         verdict + severity rules (§13)
  confidence.py      numeric confidence (§14)
  report.py          JSON / CSV / explain (§17)
  policy.py          policy load + hash (§19)
  calibrate.py       sensitivity sweep (§20.6)
```

Configuration is a declarative policy file, not constants buried in code (§19). This keeps the numbers calibratable without touching logic.
