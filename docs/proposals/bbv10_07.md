## 12. Metric families and aggregation

Percentile-per-metric alone over-counts correlated evidence. Two OP-derived
metrics both firing "high" is one economic fact, not two independent findings.

### 12.1 Families

```text
OUTPUT          damage, burst damage, sustained dps, emp
EFFICIENCY      dps_per_op, damage_per_op, damage_per_flux, range_per_op
REACH           range, projectile speed, travel time to nominal range
HANDLING        turn rate, charge time, burst length, recoil, spread
SUSTAINABILITY  flux cost, flux per use, shield efficiency, ammo economy
DIAGNOSTIC      never scored; context only
```

### 12.2 Family signal

Within family `f` the member metrics are aggregated into one signal in
`[0, 1]`, computed from oriented percentiles and enveloped excess:

```text
family_signal_f = cap( aggregate_f( member_percentiles, member_envelope ) )
```

The aggregate is deliberately conservative: it is **not** a weighted sum that
rewards piling up correlated members. The cap keeps the family signal on a
0..1 scale so that thresholds `t_over` and `t_extreme` are meaningful
(illustrative: `t_over = 0.5`, `t_extreme = 0.9`; calibration decides — §24).

`total_excess` (a summed scalar across families) may exist for **ranking
reports only**. It is explicitly **not** a decision statistic and never sets
severity.

### 12.3 Why this replaces the v0.1 weighted score

v0.1 combined every metric into a single global weighted score. That let one
entity accumulate arbitrary apparent excess by stacking correlated metrics.
The family model collapses correlated evidence into one signal per family, so
an entity is judged on **how many independent dimensions** are elevated, not
on how many times the same dimension appears.

### 12.4 Aggregation rules

* A family with fewer than one usable member is `NOT_DETERMINABLE`.
* Diagnostic metrics never enter a family signal.
* Anti-correlated members (e.g. high damage with high flux cost) pull the
  family signal toward the middle, which is the intended conservative effect.
* The report always shows the member contributions behind a family signal.

## 13. Verdict rules, severity and reason hierarchy

### 13.1 Family states

Each family is reduced to a state by comparing its signal to the tier's band:

```text
thresholds (illustrative; calibration sets the real values):
  p_band              percentile target for the tier
  t_over              family_signal above-branch threshold
  t_extreme           family_signal extreme-branch threshold
  envelope_extreme    peer_max_ratio / envelope_excess threshold for EXTREME

states:
  IN_BAND      family signal within the accepted envelope
  BORDERLINE   signal pressing on the band but not clearly past it
  ABOVE        signal clearly past the band
  EXTREME      percentile == 100 AND beyond-envelope excess past
               envelope_extreme (percentile alone saturates, see §11.2)
```

### 13.2 Verdict table

```text
0 ABOVE, <=1 BORDERLINE                  -> WITHIN_VANILLA_BAND
0 ABOVE, >=2 BORDERLINE                  -> MANUAL  (COMPOUND_BORDERLINE)
1 ABOVE                                  -> MANUAL
>=2 families ABOVE                       -> ABOVE_VANILLA_BAND
any family >= EXTREME (with corroboration) -> ABOVE_VANILLA_BAND (+ severity)
script-balance-unknown on an affected family -> MANUAL (that family)
insufficient / degenerate peers          -> MANUAL
missing critical data                    -> MANUAL
```

The `COMPOUND_BORDERLINE` row closes the hole where several suspicious
families could each stay just under `ABOVE` and quietly total to a clean
"within band." Smoke from four rooms deserves inspection.

### 13.3 Severity (only for `ABOVE_VANILLA_BAND`)

Severity is subordinate metadata; the headline verdict stays the clean
three-way model. It is derived from **independent-family counts**, never from
a summed scalar:

```text
families_above    = count(state == ABOVE)
families_extreme  = count(state == EXTREME)

>=2 families_extreme                                  -> EXTREME
(>=3 families_above AND >=1 family_extreme)           -> EXTREME
>=2 families_above                                    -> SEVERE
single severe outlier family (past t_outlier-like
  envelope threshold)                                 -> MODERATE
otherwise                                             -> LOW
```

| Internal | Display |
|---|---|
| `LOW` | Slightly overtuned |
| `MODERATE` | Overtuned |
| `SEVERE` | Severely overtuned |
| `EXTREME` | Extremely overtuned |

### 13.4 Reason hierarchy

Every verdict is explainable in one deterministic sentence, priority-ordered:

```text
1. EXTREME family evidence
2. multi-family ABOVE
3. COMPOUND_BORDERLINE
4. script uncertainty (SCRIPT_BALANCE_UNKNOWN on an affected family)
5. insufficient / degenerate peers
6. missing critical data
```

The report shows the headline reason first, then the per-family detail below.

### 13.5 Band values are not committed

`p_band` values (illustrative `standard`/`high_power`/`super`) are left
**uncommitted**. Early calibration candidates around `85 / 95 / 99` are
recorded for M6 to test; `75` is explicitly noted as possibly too aggressive
(roughly a quarter of a vanilla peer distribution sits above it). The
architecture is safe either way; the numbers come from M6.
