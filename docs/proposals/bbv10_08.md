## 14. Confidence — quality of evidence, not size of effect

Confidence answers "how good is the evidence?", never "how big is the
difference?". Internally it is numeric so it can be calibrated without
changing the public schema.

### 14.1 Numeric core

```text
confidence_score = 0.0 .. 1.0
>= 0.8  -> HIGH
>= 0.5  -> MEDIUM
else    -> LOW
```

### 14.2 Inputs

```text
peer count (vs k_min/k_max)
peer tightness (selection-space distances)
widening level (each widen lowers the score)
metric completeness (usable / expected metrics)
distribution shape (gaps, multimodality)
script certainty (per-hook states, §15)
provider completeness
topology certainty (e.g. hull mount classification)
```

### 14.3 Hard independence from magnitude

Effect size **must not** change confidence. "Extremely Overtuned, Confidence:
HIGH" and "Overtuned, Confidence: LOW" must communicate two different things:
magnitude versus evidence quality. Any coupling between them is a bug.

### 14.4 Three orthogonal axes

```text
analysis_status     coverage of the analysis
verdict             conclusion
confidence          quality of evidence
```

You can be **highly confident that you cannot decide**:

```json
{
  "analysis_status": "COMPLETE_STATIC",
  "verdict": "MANUAL",
  "manual_reason": "SCRIPT_BALANCE_UNKNOWN",
  "confidence": "HIGH"
}
```

## 15. Script evidence — graded, not binary

CSV data and runtime scripts are different evidence classes. A scripted
behaviour that static data cannot express must never be silently certified.

### 15.1 Hook states

```text
SCRIPT_COSMETIC          known, no balance consequence
SCRIPT_QUANTIFIED        known and modelled into the relevant metric
SCRIPT_BALANCE_UNKNOWN   present, balance impact not established
SCRIPT_ABSENT            no script hooks on this entity
```

`SCRIPT_BALANCE_UNKNOWN` makes the affected family `MANUAL`. An uncatalogued
on-hit effect must not land in `WITHIN_VANILLA_BAND`.

### 15.2 Propagation

```text
per-hook state -> per-family script state -> per-entity script state
```

A family with an unknown balance-relevant hook cannot be scored ABOVE or
WITHIN; it is `MANUAL`. Confidence reflects the number and importance of
unknown hooks.

### 15.3 Examples

| Hook | State | Effect |
|---|---|---|
| `onHitEffect` (cosmetic spark) | `SCRIPT_COSMETIC` | none |
| `onHitEffect` (unknown explosion) | `SCRIPT_BALANCE_UNKNOWN` | family `MANUAL` |
| custom `applyDamage` override | `SCRIPT_BALANCE_UNKNOWN` | family `MANUAL` |
| no hooks | `SCRIPT_ABSENT` | normal scoring |

## 16. Ecosystem corpus — context, not baseline

Mods are numerous and mutually inconsistent. They are useful context and
dangerous as a reference.

### 16.1 Rules

```text
The scoring baseline is VANILLA_CORE only.
Mod entities may be displayed as ecosystem context (e.g. "other mods in this
class reach X") but never blended into the vanilla baseline.
A candidate never peers against mod entities for scoring.
```

### 16.2 Why

Blending mods into the baseline imports their balance decisions as if they
were reference truth, which is exactly what a user is usually trying to
measure against. Separation keeps the question clean: "how does this compare
to **vanilla**?", with ecosystem context shown separately and labelled.

### 16.3 Invariant

`baseline.source == "VANILLA_CORE"` is a program invariant (§20.5). Changing
the ecosystem corpus must not change a vanilla-derived verdict.
