- Method link and readable version diffs (ROADMAP-3 82.8, 82.9): `research report` now decompiles with Vineflower's bytecode-source mapping (`-bsm=1 -dcl=1`, through a temporary archive because the mapping is only dumped into archive entries) and stores `<class>.lines.json` (Vineflower's pairs) and `<class>.methods.json` (each bytecode method as `a/b/C#name descriptor` with its decompiled line range, or UNMAPPED with the reason) beside the cached `.java`, keyed by jar sha256; each quoted method lists its bytecode identity. New `research diff OLD NEW [--classes TERMS] [--max-methods N] [--max-lines N] [--write DIR] [--repo CHECKOUT] [--json]` compares two versions (a jar, a mod folder or a folder holding one): the bytecode helper decides which methods changed (a per-method digest of opcodes and operands, never line numbers; `bytecode_diff.changed_methods`), then only those methods' decompiled text is shown as a unified diff, labelled STATIC, bounded, with methods that cannot be placed reported UNMAPPED. It is a `research` subcommand because it shares the decompiler cache, toolchain lookup and `--write` rules with `research report`. The bytecode helper now also reports per-method line numbers and body digests (separate `method_details` key; `bytecode-diff` output is unchanged) and prints UTF-8 with every control character escaped (a constant holding a non-ASCII character made `bytecode-inspect` crash on Windows).
